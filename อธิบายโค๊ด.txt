ส่วนที่ 1: CSS (การควบคุมการแสดงผล)
ช่วงบรรทัดที่ 7 – 122

7 – 23 (Layout Setup): กำหนด body ให้เป็น flex เพื่อดึงแอปมาไว้กึ่งกลางหน้าจอ ส่วน .container กำหนดความกว้าง max-width: 400px เพื่อจำลองขนาดหน้าจอโทรศัพท์มือถือ และใช้ box-shadow เพื่อสร้างเงาให้กล่องแอปดูลอยออกมาจากพื้นหลัง

31 – 51 (Summary Area): ออกแบบกล่องสรุปรายเดือนให้มีสีฟ้า (#e3f2fd) และใช้ display: flex กับ summary-col เพื่อแบ่งพื้นที่เป็น 3 ส่วนเท่าๆ กัน (รับ, คงเหลือ, จ่าย) ให้ดูอ่านง่าย

53 – 63 (Input Styling): ใช้ box-sizing: border-box เพื่อให้ช่องกรอกข้อมูลไม่บวมทะลุขอบเวลาเราใส่ padding (ระยะห่างด้านใน)

65 – 96 (Button Design): แยกสีปุ่มตามฟังก์ชัน: สีเขียว (#4CAF50) สำหรับรายรับที่สื่อถึงการเพิ่มขึ้น, สีแดง (#f44336) สำหรับรายจ่ายที่สื่อถึงการลดลง และสีส้ม (#ff9800) สำหรับปุ่ม Undo/Redo เพื่อเป็นสีเตือนให้ระวัง

ส่วนที่ 2: HTML (โครงสร้างและป้ายชื่อ)
ช่วงบรรทัดที่ 127 – 176

127 – 131 (Main Display): กำหนดป้ายชื่อ id="balanceDisplay" ไว้ที่ยอดเงินรวม เพื่อให้ JavaScript วิ่งมา "เขียนทับ" ตัวเลขได้ถูกต้อง

134 – 142 (Monthly Section): มี input type="month" เพื่อให้เบราว์เซอร์เปิดหน้าต่างเลือกเดือนแบบปฏิทิน และมี id แยก 3 จุด เพื่อรับผลการคำนวณแยกตามหมวดหมู่

144 – 154 (Form Fields): * id="dateInput": รับวันที่ (YYYY-MM-DD)

id="amountInput" และ id="qtyInput": รับค่าตัวเลขเพื่อนำไปคำนวณต่อ

157 – 174 (Control Buttons): ทุกปุ่มมีคำสั่ง onclick เพื่อบอกว่า "ถ้าคลิกฉัน ให้ไปเรียกฟังก์ชันนี้นะ" เช่น ปุ่มรายรับจะไปเรียก addTransaction('income')

ส่วนที่ 3: JavaScript (ระบบประมวลผล)
ช่วงบรรทัดที่ 180 – 311

180 – 181 (Memory): สร้าง "อาเรย์" (Array) 2 ชุด

transactions: คือฐานข้อมูลหลักของแอป

undoneTransactions: คือถังขยะชั่วคราวที่เก็บรายการที่เพิ่งลบไป เพื่อทำระบบ Undo/Redo

184 – 192 (Default Setting): ใช้คำสั่ง new Date() เพื่อหาเวลาปัจจุบัน และทำการ "หั่น" ตัวเลขให้ตรงตามรูปแบบที่ช่องวันที่ต้องการ (YYYY-MM-DD) เพื่อให้แอปพร้อมใช้งานทันทีที่เปิด

195 – 200 (Quick Math): ฟังก์ชัน addQuickAmount จะดึงค่าเดิมจากช่องราคามาแปลงเป็นเลข (parseFloat) แล้วบวกเพิ่มเข้าไป ทำให้กดซ้ำได้เรื่อยๆ

202 – 236 (Saving Logic): * Validation: เช็กความถูกต้อง เช่น ถ้าราคาเป็น 0 หรือช่องชื่อรายการว่างแอปจะไม่ทำงาน

Processing: สร้าง "ก้อนข้อมูล" (Object) ที่มี id จาก Date.now() (เพื่อให้ทุกรายการมีรหัสไม่ซ้ำกัน)

Storage: ใช้ .push() เพื่อเก็บข้อมูลลงอาเรย์ และล้างช่องกรอกทิ้งเพื่อให้พร้อมจดรายการถัดไป

239 – 254 (Undo/Redo Stack):

ใช้วิธี ย้ายข้อมูลไปมา ระหว่างอาเรย์หลักและอาเรย์สำรอง ด้วยคำสั่ง .pop() (ดึงอันหลังสุดออก) และ .push() (ใส่ต่อท้าย)

256 – 302 (The Update Loop - ส่วนที่สำคัญที่สุด):

Sorting (267): เรียงรายการตามวันที่ใหม่ไปเก่า เพื่อให้ผู้ใช้เห็นรายการล่าสุดอยู่บนสุดเสมอ

Iteration (271): ใช้คำสั่ง .forEach เพื่อเดินอ่านข้อมูลทีละแถวในอาเรย์

Condition Check (276): ตรวจสอบว่า tx.date (วันที่ของรายการ) ขึ้นต้นด้วยเดือนที่เลือกอยู่หรือไม่ เพื่อนำไปคำนวณสรุปรายเดือน

DOM Injection (284): สร้างแท็ก <li> ด้วยโค้ดจาวาสคริปต์ แล้วใส่ข้อมูลลงไป ก่อนจะนำไป "แปะ" บนหน้าเว็บจริง

Style Control (298): มีตรรกะเช็กว่าถ้ายอด monthlyNet < 0 ให้สั่งเปลี่ยนสีตัวอักษรเป็นสีแดงทันที

304 – 311 (Wipe Data): ฟังก์ชัน resetAll จะล้างอาเรย์ทั้ง 2 ชุดให้เป็นกล่องว่างๆ แล้วสั่งให้หน้าจอวาดตัวเองใหม่
